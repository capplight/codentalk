# База источников для курса веб-разработки

Собрано в августе 2026. Разбор устроен так же, как в
[sources-learning-materials.md](sources-learning-materials.md): главное здесь не
«что есть», а **что нам разрешено использовать на платной платформе**.

Напоминание о разнице, на которой легко обжечься: «бесплатно доступно» и
«разрешено использовать» — не одно и то же.

| Группа | Что означает |
|---|---|
| 🟢 **А. Свободно** | общественное достояние или лицензия с разрешением коммерческого использования |
| 🟡 **Б. С ограничениями** | коммерческое использование разрешено, но с условиями — чаще всего требование распространять производное на той же лицензии |
| 🔴 **В. Закрыто для нас** | запрет коммерческого использования либо обычное авторское право |

---

## Главный вывод

**С веб-разработкой нам повезло гораздо больше, чем с английским.**

Ключевые справочные материалы по HTML и CSS написаны организациями, которые
изначально выкладывали их под свободными лицензиями. Причина простая: и Mozilla,
и Google заинтересованы, чтобы веб-технологии изучали как можно шире, поэтому
разрешают брать и перерабатывать.

Для курса это означает: **можно строить программу на первоклассных источниках
законно, а не переписывать их своими словами из опасений.**

---

## 1. 🟡 MDN Web Docs — основной справочник

- **Что это.** Справочник Mozilla по HTML, CSS и JavaScript. Фактический
  отраслевой стандарт: им пользуются все разработчики, от новичков до
  создателей браузеров.
- **Лицензия.** Тексты — **Creative Commons Attribution-ShareAlike 2.5**.
  Коммерческое использование прямо разрешено. Условие: указать авторство
  («Mozilla Contributors») и распространять переработанное **на той же
  лицензии**.
- **Примеры кода — отдельно и лучше.** Всё, добавленное после 20 августа
  2010 года, находится в **общественном достоянии (CC0)**. То есть примеры
  кода можно брать вообще без условий.
- **Где.** `developer.mozilla.org`, исходники — `github.com/mdn/content`.

**Что означает требование «на той же лицензии».** Если мы возьмём текст MDN и
переработаем его в свой урок, этот урок придётся отдавать под той же свободной
лицензией. Это не мешает брать за него деньги, но означает, что кто-то сможет
взять наш урок и использовать у себя. Практический вывод: **берём у MDN факты и
примеры кода (они в общественном достоянии), а объяснения пишем свои.**

## 2. 🟡 MDN Curriculum — готовая программа обучения

- **Что это.** Отдельная разработка Mozilla: не справочник, а именно **программа
  для начинающих** — чему учить, в каком порядке, что считать освоенным.
  Составлена с оглядкой на то, что реально спрашивают у джуниоров.
- **Зачем нам.** Это ровно то, чего нам не хватало по английскому и что пришлось
  собирать из справочников уровней. Здесь готовый ответ на вопрос
  «в каком порядке давать темы».
- **Лицензия.** Та же: тексты CC-BY-SA 2.5, примеры кода CC0.
- **Где.** `github.com/mdn/curriculum`

## 3. 🟢 web.dev от Google — самая удобная лицензия

- **Что это.** Курсы «Learn HTML», «Learn CSS», «Learn Accessibility» и другие.
  Написаны практиками, разбиты на короткие уроки с проверочными вопросами —
  по устройству ближе всего к тому, что делаем мы.
- **Лицензия.** Тексты — **Creative Commons Attribution 4.0**. Примеры кода —
  Apache 2.0.
- **Почему это лучший вариант из всех.** В отличие от MDN, здесь **нет
  требования открывать переработанное**. Достаточно указать авторство. То есть
  материалы можно перерабатывать в наши уроки, не открывая их наружу.
- **Где.** `web.dev/learn`

**Практический вывод: при прочих равных берём за основу web.dev, а MDN
используем как справочник для сверки фактов.**

## 4. 🟢 Данные о поддержке браузерами

- **Can I Use** — таблицы поддержки возможностей браузерами, данные под
  **CC-BY 4.0**.
- **MDN browser-compat-data** — то же самое в машиночитаемом виде, лицензия
  CC0, то есть общественное достояние.
- **Зачем нам.** Чтобы не учить тому, что уже не работает, и честно отмечать,
  где возможность поддерживается не везде.

## 5. 🟢 Спецификации HTML и CSS

- **WHATWG HTML Living Standard** и спецификации CSS от W3C — первоисточник.
  Условия использования допускают цитирование и переработку.
- **Зачем нам.** Последняя инстанция в спорных вопросах. Для уроков сложны, но
  проверяющему методисту нужны: это тот самый внешний источник, с которым
  сверяют, а не «модель так считает».

## 6. 🔴 Закрыто для нас

**The Odin Project.** Известная бесплатная программа по веб-разработке. Лицензия
Creative Commons **с запретом коммерческого использования**: на сайте прямо
сказано, что для запуска на её основе учебного курса нужна отдельная
договорённость. Для нашей платной платформы закрыто. Смотреть, как устроено, —
можно.

**W3Schools.** Обычное авторское право. Копировать нельзя. Но именно их схема
«код слева, результат справа» — то, что владелец хочет повторить; сама по себе
идея разделения экрана не охраняется, повторять её можно.

**freeCodeCamp.** Программный код платформы под лицензией BSD-3. **Лицензия
самих учебных материалов из открытых источников не установлена** — требует
отдельной проверки до использования. Пока считаем закрытым.

## 7. Что это меняет в наших планах

**Первое. Программа курса уже написана.** MDN Curriculum отвечает на вопрос
«чему и в каком порядке учить». По английскому такого готового ответа не было,
и порядок тем пришлось бы собирать самим.

**Второе. Практика запускается сразу и бесплатно.** HTML, CSS и JavaScript
выполняются прямо в браузере в изолированной вставке — сервер не нужен, расходов
нет. Именно поэтому в техзадании курс по вебу поставлен раньше серверных языков:
Python и C# требуют выполнения кода на сервере, а это дорого и рискованно.

**Третье. Проверка знаний делается настоящей легко.** Работоспособность кода
проверяется автоматически: написал разметку — совпала ли она с ожидаемой,
получился ли нужный вид. В отличие от языков, где оценка ответа спорна, здесь
она однозначна.

**Четвёртое, важное для честности.** Курс заявлен бесплатным. Значит, требование
MDN «распространять переработанное на той же лицензии» нам почти не мешает — мы
и так не собираемся закрывать этот материал. Осторожность нужна там, где
материалы MDN попадут в **платные** курсы: там лучше опираться на web.dev.

## 8. Что осталось сделать

1. Разобрать MDN Curriculum подробно и сопоставить с нашей моделью модулей и
   уроков.
2. Установить лицензию учебных материалов freeCodeCamp — сейчас неизвестна.
3. Продумать проверку заданий по коду: сравнение разметки, проверка стилей,
   безопасность изолированной вставки.
4. Собрать источники по JavaScript отдельно — этот заход касался HTML и CSS.
5. Уточнить, как оформлять указание авторства на страницах уроков, чтобы
   выполнить условия лицензий и не загромождать вид.
