# Переезд на другой компьютер

Что переезжает само, что придётся перенести руками и чего переносить **нельзя
ни в коем случае**. Написано 20 августа 2026, когда владелец собрался
продолжать работу на ноутбуке.

## Главное в одну строку

**Опыт проверяющих, правила работы и все скрипты лежат в репозитории.** Они
переезжают обычным `git clone`, и ни один из них не потеряется. Терять нечего,
кроме трёх вещей, и все три восполнимы.

---

## 1. Чего переносить нельзя

**`.env.local` в репозиторий не кладём никогда.** Репозиторий открыт всем, и всё,
что в него попадает, считается опубликованным завтра в газете. В файле лежат
ключ доступа к базе с паролем, подпись входа и ключ синтеза речи — это не
«неудобство», это выдача чужих данных наружу.

Однажды проект на этом уже обжёгся: пароль от учебных записей лежал открытой
строкой в скрипте, а сами записи жили на рабочем сайте.

Как перенести правильно — пункт 3.

---

## 2. Что переезжает само, обычным клонированием

| Что | Где лежит |
|---|---|
| Весь код и содержание курсов | `app/`, `lib/`, `courses/` |
| **Опыт проверяющих** | `.claude/agents/metodist.md`, `.claude/agents/redaktor.md` |
| Навыки | `.claude/skills/` |
| Правила работы над проектом | `CLAUDE.md` |
| Все документы и разборы | `docs/` |
| Все скрипты проверок и озвучки | `scripts/` |
| **Записи озвучки**, 1898 файлов | `public/zvuk/` |
| Схема базы и миграции | `prisma/` |
| **Снимок памяти агента** | `docs/pamyat/` — см. пункт 4 |

Проверяющие агенты — это не «обученные модели», а два файла с правилами. Всё,
чему они научились за неделю разборов, записано в них текстом и уезжает вместе с
репозиторием.

```bash
git clone https://capplight@github.com/capplight/codentalk.git
npm ci
npx prisma generate
```

**Клонируй по тому же пути, что и здесь** — `E:\My Project\codentalk.kz`. Тогда
совпадёт имя папки проекта в `~/.claude/projects/`, и память с перепиской лягут
на своё место без правки путей.

---

## 3. Настройки — через Vercel, а не через флешку

Шесть переменных из девяти уже лежат в Vercel. Их не надо ни переписывать, ни
пересылать:

```bash
vercel login
vercel link          # выбрать проект codentalk
vercel env pull .env.local
```

Придут `DATABASE_URL`, `DIRECT_URL`, `AUTH_SECRET`, `AUTH_URL`, `RESEND_API_KEY`,
`MAIL_FROM`.

**Две переменные придётся добавить руками** — их в Vercel нет, они нужны только
для озвучки:

```
AZURE_SPEECH_KEY=…
AZURE_SPEECH_REGION=northeurope
```

Ключ бери в личном кабинете Azure, а не из старого файла: так он не пройдёт ни
через переписку, ни через флешку. Если сомневаешься, не утёк ли он, — там же
можно выпустить новый, старый перестанет работать.

## 4. Память агента

Живёт вне репозитория, в `~/.claude/projects/e--My-Project-codentalk-kz/memory/`
— тридцать восемь коротких записей: решения владельца, ошибки, на которых уже
обжигались, состояние работ. Тайного в них нет, поэтому в репозитории лежит
снимок.

```bash
npm run pamyat              # снять свежий снимок перед переездом
npm run pamyat -- --vernut  # на новом компьютере вернуть снимок в память
```

Снимок сверяется на тайное перед записью: если в памяти вдруг окажется строка,
похожая на ключ или пароль, скрипт остановится и не запишет ничего.

**Снимок — не хранилище.** Хранилище — домашняя папка, там агент читает и пишет
каждый день. Снимай снимок перед переездом, иначе увезёшь вчерашнее.

## 5. Источники — скачиваются заново

`materials/` весит 97 МБ и в репозиторий не идёт нарочно. На новом компьютере:

```bash
bash scripts/download-sources.sh
npm run md          # второй разбор PDF, нужен для сверки цитат
```

Разборы PDF (`materials/.text/`, `materials/.md/`) — кэш, собирается сам при
первом обращении.

Что скрипт скачать не может и придётся взять руками: словник English Vocabulary
Profile (нужна регистрация — п. 2.2 в [zadachi-vladeltsa.md](zadachi-vladeltsa.md)).

---

## 6. Переписка — если хочется

Записи разговоров лежат в `~/.claude/projects/e--My-Project-codentalk-kz/*.jsonl`.
Их можно скопировать, и при совпадающем пути они подхватятся.

Но честно: **переписка — это журнал, а не знание.** Всё, что в ней стоило
сохранить, уже вынуто в файлы — правила в `CLAUDE.md`, решения в `docs/`, память
в `docs/pamyat/`, опыт проверяющих в `.claude/agents/`. Это и есть правило
храповика: каждый разбор оставляет след не в переписке, а в файле, который
прочтёт следующая сессия.

## Порядок действий на новом компьютере

```bash
# 1. Забрать код (по тому же пути, что на старой машине)
git clone https://capplight@github.com/capplight/codentalk.git
cd codentalk
npm ci
npx prisma generate

# 2. Настройки
vercel login && vercel link && vercel env pull .env.local
#    и дописать в .env.local две строки AZURE_SPEECH_*

# 3. Память агента
npm run pamyat -- --vernut

# 4. Источники
bash scripts/download-sources.sh
npm run md

# 5. Проверить, что всё на месте
npm test
npm run check:content
npm run kontrol -- english-starter
```

Если последние три команды прошли — переезд состоялся: содержание целое, записи
на месте, проверки работают.
