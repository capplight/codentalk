Владелец 13 августа 2026: «скрипт меня разочаровал» — о правке учебного текста
регулярными выражениями. Решение: **содержание правится по одному месту с
чтением окружения.** Скрипт замены — только для механического по всему курсу
(предлог `at`, переименование термина).

**Why:** счёт за одну сессию. Скриптовые правки дали: верную английскую фразу
`Yes, I do work`, заменённую на бессмыслицу `Yes, I am work`; три разбора
задания, оставшихся от прежних вариантов; два сломанных файла; **два одинаковых
варианта в одном задании, доехавших до боевого сайта**. Причина у всех одна:
заменялась строка, а не читалось место.

**How to apply:** правишь — открываешь блок целиком, читаешь условие, все
варианты и разбор, и только потом меняешь. После правки — `npm run zadaniya`.

## Четыре правила того же разбора

1. **Никогда не писать «в источнике этого нет».** Писать «не нашёл, проверить»
   и называть, где искал. За сессию это утверждение не выдержало проверки
   четырежды: `have got`, `o'clock`, короткий ответ `Yes, I do`,
   `What do you do?`. Причина всегда одна — ищу по слову, которым правило
   называю я, а источник называет его своим. Отсутствие утверждает только
   методист, открывший файл.
2. **После правки перечитывать задание целиком**, а не строку.
3. **Докладывать по `git diff`, а не по памяти.** Список из восьми правок,
   названный по памяти, разошёлся с настоящим, и методист разбирал не то.
4. **Любая правка видимого текста — новое содержание**, на сайт без
   проверяющего не идёт. Я это правило применил к модулю 17 и в тот же день сам
   нарушил, выложив восемь изменённых строк.
