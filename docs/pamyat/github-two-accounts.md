На компьютере владельца два аккаунта GitHub. **Корпоративный — рабочий, его не трогаем ни при каких обстоятельствах.** CodeNTalk живёт в личном: `github.com/capplight/codentalk` (приватный).

**В чём была ловушка.** Хранилище паролей Windows по умолчанию отдавало git ключ корпоративного аккаунта. Отправка падала с `Permission ... denied`, будто нет прав, хотя дело было в лице: подпись коммитов личная, а ключ подставлялся рабочий. Окно выбора аккаунта показать некуда — я работаю без взаимодействия, поэтому вместо окна сразу отказ.

**Решение — имя в адресе:**

```
git remote set-url origin https://capplight@github.com/capplight/codentalk.git
```

Хранилище ищет ключ по паре «узел + имя», поэтому берёт личный и не задевает корпоративный. Настройка лежит в `.git/config` этого репозитория, глобального ничего не меняли — `gh auth login` и `gh auth setup-git` НЕ запускали намеренно: они настраивают вход глобально и повлияли бы на рабочие репозитории.

Если ловушка вернётся в другом репозитории проекта — лечится тем же приёмом, а не входом заново.
