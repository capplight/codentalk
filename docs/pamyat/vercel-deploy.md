и переписывать прежнюю версию (10 августа 2026).

Не путать с GitHub, где две учётные записи и корпоративную трогать нельзя —
[[github-two-accounts]].

## Что было сломано и починено

В Vercel **не было ни одной переменной окружения**. Выкладка тринадцатидневной
давности стояла без адреса базы и без ключа входа: любая страница с базой
падала, войти было нельзя.

Заведены четыре, все из локального `.env.local`:
`DATABASE_URL`, `DIRECT_URL`, `AUTH_SECRET`, а `AUTH_URL` —
`https://codentalk.vercel.app`.

**Если появится новая переменная в `.env.local` — её надо добавить и в Vercel
вручную**, иначе сборка пройдёт, а страница упадёт.

## Команда

```
npx vercel deploy --prod --yes
```

Раньше блокировалась правами; сейчас проходит. Перед выкладкой:
`npm run check:content`, `npm run db:seed:courses`, `npm run build`.

## ПУШ В РЕПОЗИТОРИЙ ВЫКЛАДКУ НЕ ЗАПУСКАЕТ

Выяснено 14 августа 2026. Я отправил шестьдесят коммитов в `main` и ждал, что
Vercel соберёт сам, — он не собрал. `npx vercel ls` показал, что последние
выкладки двухдневной давности и все сделаны рукой.

**Коммит не равен выкладке.** Выкладывать только командой, и после неё
проверять боевой сайт: обещать владельцу выложенное, не убедившись, нельзя.

## Что важно помнить

- Домен `codentalk.kz` РАБОТАЕТ (проверено 14 августа: главная и страница
  модулей отвечают). Прежняя запись о неотвечающем домене устарела.
- Сайт **закрыт от поисковых систем**: `robots.txt` запрещает обход целиком.
  Так задумано до команды владельца о запуске.
- Локальная проверка — порт **3010**; запущенный из моей оболочки сервер
  умирает вскоре после конца ответа, надёжнее владельцу запускать самому.
