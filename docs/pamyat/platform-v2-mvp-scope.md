Границы MVP для [[platform-v2-vision]], согласованные с владельцем в августе 2026. Разработка ещё не начата — на момент записи следующий шаг — написать полное техническое задание одним документом.

**Ключевые продуктовые решения (приняты явно, не выводимы из кода):**
- **БЕЗ drip-контента и БЕЗ календаря.** Все уроки доступны сразу. Вместо расписания — **рекомендованный порядок** (урок 1 → 2 → 3, но перепрыгивать можно). Обосновано как «80% пользы за 20% сложности»; календарь без drip признан шумом в интерфейсе.
- Раз drip нет, уроки нужно **дробить так, чтобы не перегружать**, и обязательно давать вернуться туда, где остановился (сохранение позиции — требование владельца).
- **Видеоуроков не будет вообще.** Самостоятельное обучение по материалам, но увлекательное. Это снимает video player и хостинг видео из архитектуры.
- **Тесты — настоящие и серьёзные**, обучающие материалы реальные: владелец требует, чтобы ученики получали действительные знания, а не проходили формальность.
- Первый курс — **английский**; учебники предоставит владелец, программу составляем вместе, по одной теме за раз, с доскональным разбором учебников.
- Сертификаты — **PDF** (достаточно; онлайн-бейджи с верификацией отвергнуты как усложнение).

**Входит в MVP:** регистрация и авторизация (email+пароль, без OAuth), каталог курсов и уроков, отметка «урок пройден», тесты с оценкой, PDF-сертификат, профиль с прогрессом.

**Осознанно отложено (не делать в MVP):** выполнение кода в браузере, drip-контент, AI-наставник, реальные платежи Stripe, мобильное приложение, комментарии/Q&A, система достижений, OAuth/SSO.

**Заглушки, которые нужно заложить в архитектуру СРАЗУ** (владелец отдельно подчеркнул: «нужно в архитектуре оставить место» для AI и платежей):
- Code execution: модель Exercise (problem_id, input, expected_output) + `POST /exercise/:id/submit`, возвращающий заглушку. Владелец настаивает, что программирование без практики на месте не имеет смысла (аналог W3Schools: код слева, результат справа) — это обязательная будущая фича, не опциональная.
- AI-наставник: таблица чатов (user_id, lesson_id, messages) + `POST /chat/ask` на FAQ из БД. Владелец говорит, что уже делал подобное, поэтому технически это не блокер. Отдельные агенты обучаются под каждый курс.
- Платежи: модель Subscription (user_id, status, next_billing_date) + поле `subscription_status` у пользователя + переключатель free ↔ premium заглушкой.
- Drip: поле `Lesson.available_at` (null = доступен сразу).

**Предложенный стек (обсуждался, окончательно не утверждён):** Next.js на фронте, Node/Express или Django на бэке, PostgreSQL, JWT или Firebase Auth, Stripe для платежей, Docker-песочница для выполнения кода, Redis для сессий и прогресса, S3/Cloudflare R2 для файлов.

**Оценка сроков не задана** — владелец сказал «неважно, времени много», поэтому фазировать надо по объёму работ, а не по календарю.
