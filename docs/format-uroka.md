# Формат урока

Предложение к обсуждению. Август 2026.

Здесь сходятся три вещи: [стандарт содержания](standart-soderzhaniya.md),
страница урока и автоматические проверки целостности. Ошибка в формате дорога:
на нём будут написаны сотни уроков.

---

## На что опираемся

Формат не выдуман с нуля. Под ним три опоры, каждую можно проверить.

**QTI 3.0** — отраслевой стандарт описания заданий и проверочных работ,
выпущен 1EdTech в мае 2022 года. Он отвечает на вопрос «какие бывают виды
заданий». Наш набор — его подмножество: берём то, что нужно языкам и
программированию, и называем так же. Выигрыш не теоретический: если однажды
понадобится вывезти банк вопросов в другую систему или ввезти чужой, у нас
будет общий язык, а не свой велосипед.

**Обратное проектирование.** Сначала формулируется проверяемый итог, затем
проверка, и лишь потом само занятие. Это прямо отвечает требованию «ученик
должен получить знания, а не потратить время»: у каждой единицы времени есть
проверяемое умение.

**Практика припоминания.** Обзоры дают средний размер эффекта около 0,50 в
пользу припоминания по сравнению с перечитыванием. Отсюда правило: **задания на
выбор из вариантов — меньшинство**, потому что узнать среди подсказок легче,
чем достать из памяти. Основу составляют вставка, восстановление порядка и
короткий свободный ответ.

Честная оговорка: эффект интервальных повторений зависит от предмета сильнее,
чем принято думать — в математике мета-обзор даёт около 0,18 с доверительным
промежутком, задевающим ноль. Интервальные повторения закладываем, но чудес от
них не ждём и на витрине не обещаем.

## Иерархия

```
Курс (ступень)
 └── Модуль (одна тема)
      ├── источники        — внутреннее поле, наружу не уходит
      ├── итоги            — что ученик будет уметь
      └── Уроки
           ├── итог урока  — одна проверяемая формулировка
           └── Блоки       — материал и задания вперемешку
```

## Блоки материала — закрытый набор

Шесть видов. Расширяется только программированием, поэтому набор намеренно мал.

| Вид | Что это | Зачем именно он |
|---|---|---|
| `explain` | Абзацы объяснения | Основа. Серифный шрифт, течёт по странице |
| `example` | Разобранный пример | Разбор до самостоятельной попытки снижает нагрузку на память и ускоряет освоение |
| `table` | Таблица | Формы, спряжения, сопоставления — то, что списком не читается |
| `note` | Короткая врезка | «Обрати внимание», типичная ошибка |
| `audio` | Звук с расшифровкой | Аудирование. Расшифровка обязательна |
| `image` | Изображение с подписью | Схемы, разметка страницы |

## Задания — закрытый набор

Названия и смысл взяты у QTI 3.0, чтобы не расходиться со стандартом.

| Вид | Соответствие в QTI | Что делает ученик |
|---|---|---|
| `choice` | choiceInteraction | Выбирает один вариант |
| `multi` | choiceInteraction (multiple) | Выбирает несколько |
| `gap` | textEntry / gapMatch | Вставляет пропущенное |
| `order` | orderInteraction | Восстанавливает порядок |
| `match` | matchInteraction | Сопоставляет пары |
| `short` | textEntryInteraction | Пишет короткий ответ, сверка по приведённой форме |
| `essay` | extendedTextInteraction | Пишет развёрнутый ответ, есть эталон и чек-лист |
| `code` | portable custom interaction | Пишет код, видит результат |
| `speak` | вне стандарта | Произносит вслух, браузер слушает |

**Правило соотношения.** Задания `choice` и `multi` — не больше трети от всех в
модуле. Остальное требует произвести ответ, а не узнать его.

## Итог урока и проверяемость

У каждого урока ровно одна формулировка вида «умеет…», написанная по образцу
описаний Совета Европы.

Правило, которое проверяется скриптом: **у каждого итога урока должен найтись
хотя бы один вопрос в проверочной работе модуля, помеченный тем же итогом.**
Урок, чей итог ничем не проверяется, — это потраченное время ученика.

## Источники модуля

Внутреннее поле, ученику не показывается. Причина и границы — в разделе 5
[стандарта содержания](standart-soderzhaniya.md).

## Как это выглядит в файле

Пример нарочно не английский, чтобы обсуждать форму, а не содержание. Взят
первый модуль введения в веб-разработку — тема, по которой у нас есть источники
под свободными лицензиями.

```ts
import type { Module } from "@/lib/content/types";

const module: Module = {
  slug: "html-tekst",
  title: "Текст на странице",

  // Внутреннее: наружу не уходит, нужно проверяющему
  sources: [
    { ref: "MDN Web Docs", section: "HTML basics: text fundamentals", license: "CC-BY-SA 2.5" },
    { ref: "web.dev", section: "Learn HTML: Headings and sections", license: "CC-BY 4.0" },
  ],

  outcomes: [
    "размечает заголовки и абзацы так, чтобы браузер понимал структуру",
    "выбирает уровень заголовка по смыслу, а не по размеру шрифта",
  ],

  lessons: [
    {
      slug: "zagolovki-i-abzacy",
      title: "Заголовки и абзацы",
      estimatedMinutes: 12,
      outcome: "размечает заголовки и абзацы так, чтобы браузер понимал структуру",

      blocks: [
        {
          kind: "explain",
          text: [
            "Браузер не видит, что текст крупный и жирный — он видит теги. " +
              "Заголовок обозначается тегом h1, обычный текст — тегом p.",
            "Это нужно не для красоты. По заголовкам страницу читают программы " +
              "чтения с экрана и поисковые системы: они строят по ним оглавление.",
          ],
        },
        {
          // Разобранный пример до самостоятельной попытки — снижает нагрузку
          kind: "example",
          caption: "Как это выглядит",
          code: "<h1>Рецепт борща</h1>\n<p>Сначала сварите бульон.</p>",
          explain: "Первая строка — заголовок страницы. Вторая — обычный абзац.",
        },
        {
          kind: "note",
          tone: "mistake",
          text: "Частая ошибка: брать h2 вместо h1 потому, что h1 «слишком крупный». Размер меняется стилями, а уровень заголовка — это смысл.",
        },
        {
          kind: "gap",
          prompt: "Допишите тег, чтобы строка стала заголовком страницы.",
          before: "<",
          after: ">Рецепт борща</h1>",
          answer: "h1",
          hint: "Заголовок самого верхнего уровня.",
          why: "h1 — заголовок страницы. Он на странице один.",
        },
        {
          kind: "order",
          prompt: "Расставьте строки так, чтобы получилась осмысленная страница.",
          items: ["<h1>Кофе</h1>", "<p>Молотый кофе заливают горячей водой.</p>", "<h2>Как заваривать</h2>"],
          answer: [0, 2, 1],
          why: "Сначала заголовок страницы, потом заголовок раздела, потом текст раздела.",
        },
        {
          kind: "code",
          prompt: "Сделайте страницу с заголовком «Мой первый сайт» и одним абзацем под ним.",
          starter: "",
          check: { mustContain: ["<h1>", "</h1>", "<p>", "</p>"] },
          why: "Заголовок задаёт тему страницы, абзац — её содержание.",
        },
      ],
    },
  ],
};

export default module;
```

## Что проверяет скрипт

Автоматически, до показа человеку:

- у каждого урока есть итог, и он покрыт хотя бы одним вопросом проверочной;
- у модуля заполнены источники;
- в задании `order` ответ — перестановка всех позиций, без пропусков и повторов;
- в задании `gap` ответ не пустой;
- в `choice` ровно один правильный вариант;
- доля `choice` и `multi` в модуле не превышает трети;
- положение правильного ответа в банке вопросов распределено равномерно;
- время урока укладывается в 8–15 минут по числу блоков.

## Что решить

1. **Набор блоков материала** — шести хватает или чего-то не хватает?
2. **Набор заданий** — девять видов. Лишние есть? Недостающие?
3. **Правило «не больше трети на выбор»** — принимаем или мягче?
4. **Итог урока как обязательное поле с проверкой покрытия** — принимаем?
